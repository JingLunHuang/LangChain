# 開發者筆記

## 核心設計理念

在建構這個 Agent Platform 時，我主要的設計初衷是打造一個能夠投入生產環境的通用型框架。過去很多 Agent 的實作都只停留在腳本層面，缺乏統一的存取介面、擴展性與多租戶隔離。因此，我將重點放在框架邊界與輸入管理，提供可高度擴展的工具鏈。

工具的設計上要有清楚的輸入、輸出與描述，Agent 才能精確地選擇適合的操作。例如在網路診斷模組中，展示了多個工具如何無縫串聯；記憶管理機制則讓每輪對話能有效帶上前下文。

## 平臺的整合設計

我將 LangChain 定位為工具決策與調度層，把 LlamaIndex 定位為資料層；兩者透過標準工具合約互通。混合檢索實際合併向量與 BM25，回傳來源讓答案可被追溯與檢查。這是基於現有演算法的整合設計，以確保系統在處理大量數據時的檢索品質。

MCP (Model Context Protocol) 不僅僅是作為外接工具：平臺本身提供原生 MCP Server，讓其他客戶端能直接取得檢索與 Agent 能力；Client adapter 則負責保留工具 schema。API 另外加入了 Key 管理、租戶隔離、有限的會話保存與真正的流式傳輸 (Streaming)，將單次的腳本執行徹底轉換成能持續服務的平台架構。

快取與效能方面，我選擇了可在應用層驗證的策略：固定前綴 (System Prompts)、固定工具順序、輸入 Token 預算、保留最新問題與明確的歷史摘要壓縮。前綴固定能完美適配底層推理後端（如 vLLM）的 PagedAttention 與 Prefix Caching 機制，極大地提升了 GPU KV Cache 的重用率。

## 未來發展與邊界

本平臺目前的範圍是一個可重現的高效能單程序架構。後續若要做為超大規模的商用 SaaS 服務，架構上應針對分散式會話持久化 (如 Redis)、全域權限控制、配額 (Quota)、API 限流 (Rate Limiting)、知識庫即時索引更新 (Ingestion)、摘要質量監控與推理後端路由設計新的擴展模組。
